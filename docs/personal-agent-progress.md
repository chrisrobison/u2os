Job research workflow (#250): an unsaved web-only starter and [owner walkthrough](job-research-walkthrough.md) exercise two bounded fixture passes with evidence-based fit/mismatch explanations, retained owner review, new/repeated indexed links, reload, cumulative spending and pause. Finite research (#252) adds an owner/revision-bound web-only API, daily-or-slower pass limits, persistent scheduler checkpoints and status view; native creation (#254) adds explicit start/interval/count inputs with saved-scope and remaining-budget notices. Fixtures cover idle/concurrent/restarted ticks, no catch-up bursts, failed/uncertain/no-read outcomes, cumulative budgets, rollback, migration, bounded scan fairness, auth/CSRF, browser creation/reload/lifecycle, invalid/unsaved input, stale revisions and unavailable scopes/budgets. These are deterministic orchestration tests, not live search validation or proof of real-model relevance quality. Operational hardening and owner-driven quality validation remain.

Deferred: native mobile/watch apps, broad connector catalog, hosted service, multi-device sync, and a coding runner. A coding runner needs its own scoped design with isolated workspace, filesystem and resource boundaries, Git, tests, and artifact handling.

Startup bind safeguard (#262): queue, sync and trigger workers start only after successful HTTP bind; bind rejection cleans prepared device adapters. Isolated occupied-port fixtures preserve queued rows and zero attempts in fresh/configured personal homes, clear heartbeat resources and leave another running home's workers intact; successful-bind/close fixtures retain configured timers. Worker-setup failure after bind closes the listener and drains partial setup. An idempotent internal background drain does not close HTTP or cancel pending request handlers. Local initialization can still precede binding. Cross-process singleton/maintenance locking, complete runtime shutdown and safe backup/restore remain unfinished.

Sync lifecycle (#260): same-home/domain/provider/account polling and manual calls share one in-flight operation, including sanitized failures. Other accounts/domains/homes stay independent; reconciliation preserves work without catch-up retries. An awaited timer shutdown drains already-started operations without claiming cancellation. Deterministic entry/release and captured-timer fixtures cover overlap, switches, failures, retries, stale callbacks and success/failure drain. This is a recovery prerequisite, not yet a complete runtime/maintenance lock or safe live backup; no live sync validation was performed.

Device execution boundary (#256): raw invoke/test/stream-open routes deny before adapter access by default and in production; only explicit non-production development opt-in enables them. Native controls fail closed on missing debug metadata. Fixtures cover not-attempted denials, forged flags, production override, session/CSRF, revocation, unchanged policy-gated presentation, metadata/discovery, and browser disabled/development/unknown states. Personal mock-device separation (#258) confines mock adapters to explicit demo homes; cached legacy mock and real records preserve owner edits/trust but cannot resolve without their adapter. APIs and native views distinguish demo provenance, adapter registration and last observation. Fresh, upgraded, restarted, failed-real and demo fixtures cover the boundary; no live hardware validation was performed. Consistent encrypted backup/restore and broader outage recovery remain.
